6 · Perbandingan Pemrosesan Sisi Server vs Sisi Client

Sisi client (OpenCV.js & face-api.js di atas) memproses gambar langsung di peramban tanpa mengirim data ke luar perangkat. Bagian ini mengukur/mengestimasi jalur sisi server: gambar diunggah ke API eksternal, diproses di server, lalu hasil dikirim kembali — untuk dibandingkan dengan latensi client yang sudah tercatat.

Belum cukup data — jalankan trial client (bagian 4) dan uji server di atas.
Model estimasi simulasi: Total ≈ RTT + (Ukuran Payload × 8 / Bandwidth Unggah) + Waktu Proses Server + (Ukuran Respons × 8 / Bandwidth Unduh), dengan ukuran respons diasumsikan kecil (~2 KB berupa JSON koordinat/label). Mode "API Sungguhan" mengukur waktu tempuh fetch() end-to-end secara langsung dari browser ke endpoint yang dikonfigurasi. Perbandingan ini menyoroti trade-off klasik: pemrosesan client menghindari overhead jaringan dan menjaga data tetap di perangkat (lebih privat), sedangkan pemrosesan server dapat memanfaatkan komputasi lebih besar namun bergantung pada kondisi jaringan dan konsumsi bandwidth.
Pipeline OpenCV.js: Haar Cascade → wajah terbesar → LBP histogram 100×100 → cosine similarity (konsisten dengan instrumen pilot sebelumnya). Pipeline face-api.js: TinyFaceDetector → 68-point landmarks → 128-D descriptor → euclidean distance. Metrik precision/recall dihitung sebagai tugas verifikasi identitas: benar jika prediksi cocok dengan ground truth (termasuk penolakan yang tepat untuk kondisi "Tidak Dikenal"). Data tidak disimpan permanen di peramban — unduh CSV/JSON setiap sesi untuk diarsipkan dan dianalisis statistik (mis. ANOVA, η²) di luar instrumen ini.
